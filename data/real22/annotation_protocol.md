# 真实截图真值标注规范

> 目的：让 22 条样本的真值由**同一套标准**产出。
> 标准若漂移，"真值"就只是另一个人的主观判断，整条实验链失去地面基准。
>
> 本文件在标注**开始之后**才建立，因此**前几条如果与本规范不一致，以后者为准并回改**。

---

## 一、真值是什么

**真值 = 你在图上能读到的文字，逐字照抄。**

它**不是**"这段文字应该是什么"，而是"这段文字**实际印的是什么**"。
两者的差别是本规范的全部要点。

---

## 二、三条硬纪律

| # | 纪律 | 反例 |
|---|---|---|
| 1 | **照抄所见** | 图上是全角 `１２３`，就写全角；不许"顺手"转半角 |
| 2 | **原文错字照抄** | 图上印 `iostrean`、`satrt`，就写 `iostrean`、`satrt`；**不许修正** |
| 3 | **标点形态照抄** | 图上是全角冒号 `：` 就写全角；是 `...` 就写三点，不许统一成 `…` |

**纪律 1 与 2 的理由**：全角/半角、繁简、标点形态**正是本项目要测的那几档协议**。
若标注时就把它们归一，等于**在真值阶段就把自变量抹掉了**，实验将测不出任何差异。

**纪律 3 的理由**：真值是标准答案。把原文的错改成对的，
等于**替模型掩盖或制造了一个错误**，直接污染结论。

## 三、判读顺序（关键，不可颠倒）

```
① 先看字形
      ↓ 分不清时才进入第二步
② 用语法 / 语义兜底
      ↓
③ 还是分不清 → 按下方「约定」选一个、记录、继续
```

### 为什么顺序不能颠倒

语法判断只能用来回答「**印的是哪个字**」，
**绝不能**用来回答「**应该是什么字**」。

> ❌ 危险示范：图上印 `iostrean`，你按英语常识改成 `iostream`。
> 模型照抄了原文的错（它答对了），却被记成答错。**标准答案被注水。**

### 同图对比法（判字形的可靠手段）

拿**同一张图里一个确定的字符**，去比一个不确定的字符。

> 同一张图、同一字体、同一渲染 → 两个字符若长得不一样，**它们就不是同一个字**。

这比"盯着看"可靠得多，因为它排除了字体、渲染、缩放带来的干扰。

## 四、边界约定（一次定好，全部样本统一执行）

| 情形 | 约定 | 理由 |
|---|---|---|
| **界面图标**（如 `≡`、`⚙`、`▶`） | **不写** | 图标不是文字 |
| **文字按钮 / 标签**（如「搜索」「筛选」） | **写** | 它是文字 |
| **分割线、装饰符号** | **不写** | 非文字元素 |
| **图片、缩略图、头像** | **不写** | 真值只覆盖文字 |
| **几何图形内的字母/数字标注**（如正方体顶点 `A` `B` `C_1`） | **不写** | 它们虽是文字，但**散布在图中，阅读顺序没有唯一正确答案**。写入会引入与协议无关的排序噪声 —— 同一张图不同人排出的先后不同，差异会被记成模型的错 |
| **图片内的水印、页眉页脚** | 按是否属正文判断；页眉页脚**写**（有固定阅读位置），水印**不写** | |

> 依据：机器稿曾把筛选图标 `≡` 认成汉字「三」写进真值。
> 这类"字与图元的边界"必须在标注前统一，否则同一个图标在不同样本里会被写/不写，引入与协议无关的噪声。

---

## 五、拿不准时的处理（不要卡住）

**一个人的判断不该阻塞整条流水线。**

规则：**先用同图对比法尽力判 → 仍拿不准 → 按本规范的约定选一个、记录、继续。**

**为什么可以这样**：单个字符的判断误差对**语料级 CER** 的影响是千分之几；
而它为你在另外 21 条上省下的时间，价值高得多。

### 已生效的约定（后续样本沿用）

| 编号 | 情形 | 约定 |
|---|---|---|
| C-01 | 字与字之间的**长横杠**（破折号） | **记为 `——`（两个字符）**。理由是中文破折号本就占两个字宽。**该条已由人工核验修正**：首版曾定为一个 `—`，在 `real_0001` / `real_0008` 上均被人工核验纠正为两个 |
| C-02 | 竖排分隔用的长竖线 | **记为 `\|`**（半角竖线），不用 `丨`（汉字竖） |
| C-03 | **数学上标**（如 `x²`） | **用 Unicode 上标字符**：`x²` `x³` `x⁴` `xⁿ`。**不得**写成 `x^2` 或 `x2` |
| C-04 | **数学下标**（如补集符号 `C` 右下角的小 `U`） | **用 `_` 显式标注**：`C_U A`。理由见下 |
| C-05 | 集合与运算符号 | **用 Unicode 原字符**：`{` `}` `∪` `∩` `∈` `∉` `≤` `≥` `≠` `√` `−`（减号）`×` `÷` |
| C-06 | **空格** | 只记**功能性分隔**产生的空位：编号与正文之间（`1. D`）、答案字母与详解之间（`D 【详解】`）、逗号之后（`, 则`）。**数学式内部一律不加空格**（`y=-11.7+1370.7`、`所以y与x负相关`） |
| C-07 | **堆叠分数**（分子分母上下排列） | 用**斜杠行内式**：`a/b`。分子分母都是整体时加括号：`(a_{i_2}-a_{i_1})/(a_{i_2}-a_{i_1})` |
| C-08 | **求和/连乘号及其上下限** | 用 `∑` / `∏` 加下标式上下限：`∑_{j=i_t}^{i_{t+1}-1}`。**上下限顺序为「下标 上标」**（LaTeX 习惯） |
| C-09 | **数学省略号** | 数学式内用 `⋯`（居中）；正文叙述用 `...`。**两者不同，照抄所见** |
| C-10 | **中英文之间的空格** | 英文词紧邻中文处**按图判断**：图上有明显间隔就记一个半角空格（`if 引导`），没有就不记 |
| C-11 | **换行与分段** | **保留图上可见的换行**；段落之间**保留空行**。理由见下 |
| C-12 | **表格** | **按行记录**，每行一行；单元格之间用**单个半角空格**分隔；行内换行的单元格内容合并 |
| C-13 | **行内符号 vs 界面图标** | 判据按**符号类型**而非位置，见下：<br>**写**——有唯一标准 Unicode 字符可忠实表示的符号：`✓` `✕` `★` `→` `℃` `%` `°`<br>**不写**——**彩色图形图标**，无对应字符：Apple 的 Wi-Fi 扇形、App 图标、按钮图形、工具栏图标、排序箭头 `▾`、放大镜 `🔍` |
| C-14 | **代码/编辑器截图** | **保留缩进**；**代码行号不写**（编辑器行号属界面装饰，且会与代码数字混淆） |
| C-15 | **思维导图** | 按**深度优先**（根 → 第一分支及其全部子节点 → 下一分支）。**该顺序是本规范的约定，不是图形的唯一解** |
| C-16 | **多栏 / 侧边栏 + 主区** | **主内容区优先，侧边栏其次**；多栏并列时**按块读**（左块读完再读右块），**不逐行交叉** |

### C-15 / C-16 的顺序约定声明（必须随结论一起说）

**版面越复杂，阅读顺序越没有唯一解。** 我们对每类版式选**一条约定**统一执行：

| 版式 | 约定 |
|---|---|
| 文章 / 说明 | 从上到下、从左到右 |
| 表格 | 按行（C-12） |
| 树 / 思维导图 | 深度优先（C-15） |
| 多栏 / 侧边栏 | 主内容优先、按块（C-16） |

> **必须声明的事实**：这些是**我们的约定**，不是图形的客观唯一解。
> 换一个团队可能排出另一种同样合理的顺序。
>
> **后果**：含这类版式的样本，其误差中**含有"排序习惯差异"这一成分**，
> 而它与六档协议无关。因此：
> 1. 引用这些样本的分数时，**必须同时声明"含版式类样本，顺序按约定处理"**；
> 2. 它们对"协议敏感性"的贡献低于纯文字样本，**不作为结论的主要依据**。
>
> **为什么不干脆剔除**：如实保留并声明，比悄悄剔除更符合本项目的作风 ——
> 剔除会让"只报对自己有利的样本"成为无法证伪的指控。

### C-11 为什么保留换行，而不是把段内换行合并

**曾考虑合并段内换行（更接近"逻辑文本"）——被否决**，理由有两条，第二条是决定性的：

1. **照抄所见**：换行是眼睛能看到的事实。
2. **换行正是三种切分要测的东西**。`whole` / `para` / `para_merge` 三个口径的差别，
   本质就是"怎么看待行与段"。**若在真值阶段就把换行抹平，等于替模型把这一档的差异先消掉** ——
   与纪律 1、2 犯的是同一个错。

> **代价（已知并接受）**：真值的换行取决于**截图时的屏幕宽度**。
> 同一篇文章用不同宽度截图，真值会不同。这确实降低了"跨截图可比性"。
> 但把它合并同样会引入另一种不可复现性（"哪些算段内换行"需要逐处判断）。
> 两害相权，选择**保留所见**这一条可机械执行的规则。

### C-13 判据的三次演进（含被否决的版本）

| 版本 | 判据 | 被否决的原因 |
|---|---|---|
| ① | **图标一律不写** | 太粗：正文里的 `✓`、`℃`、`%` 也被一刀切掉，句子都不完整了 |
| ② | **把它删掉，句子还通吗？** 通 → 不写 | **实做中失效**。`real_0016` 里 `the Wi-Fi icon 📶 in`：句子本来就写着 "the Wi-Fi icon"，删掉图标照样通顺 —— 判据指向了错误答案 |
| **③（定稿）** | **看符号类型**（见下表） | 可机械执行，不依赖对句意的判断 |

| 类型 | 处理 | 例 |
|---|---|---|
| **有唯一标准 Unicode 字符可忠实表示** | **写** | `✓` `✕` `★` `→` `℃` `%` `°` |
| **彩色图形图标，无对应字符** | **不写** | Apple 的 Wi-Fi 扇形、App 图标、按钮图形、`🔍`、`▾` |

> **③ 的理由（关键）**：真值里若出现"我们拍脑袋选的字符"（如用 `📶` 表示 Apple 的扇形图标），
> 模型就会因为**没按我们的写法输出**而扣分 —— **扣的不是它的能力，是我们的约定**。
> 这种分数是脏的，必须避免。

### C-07~C-09 的适用声明（重要）

堆叠分数、求和号、居中省略号这三类，**必须把印刷的二维排版压成一行**，
因此必然引入"我们的表示法"而非原样照抄。**这不是疏忽，是无法避免的** ——
纯文本没有二维结构。

故：**凡是含 C-07~C-09 的样本，其真值带有「表示法约定」成分**，
在报告中引用这类样本的分数时须一并声明。

**选择斜杠式而非维持二维的理由**：真值要能被**逐个字符比较**（编辑距离的前提）。
任何需要"先解析二维结构"才能比较的表示，都会把解析差异混进字符差异里 ——
那是与协议敏感性无关的噪声。

### C-06 为什么按"功能"判断，而不是按"像素宽度"

**本条经过三次修订，前两版均被实做否决 —— 记录如下，避免以后重犯。**

| 版本 | 规则 | 被否决的原因 |
|---|---|---|
| ① | 数学式内部的**排版间距不计**，只记正文词间空格 | 需要在 662×816 的分辨率下**区分"排版引擎生成的间距"与"人为加的空格"** —— 实际做不到 |
| ② | **肉眼可见的明显间隙就记** | "明显"仍需逐处判断，且数学式里到处是间隙 → 真值会被几百个空格淹没，**标注者无法稳定复现自己的判断** |
| **③（定稿）** | 只记**功能性分隔**的空位 | 判据是**"这个空位在分隔什么"**，而非"它有多宽" —— 可执行、可复核 |

> **教训**：一条标注者自己也执行不稳定的规则，**比没有规则更糟** ——
> 它会让 22 条样本写出 22 种风格，而真值标准一旦漂移就无法再作为基准。

**判据（定稿版）**：问自己"**这个空位隔开的是两个不同的内容单元吗？**"

| 记 | 例子 | 理由 |
|---|---|---|
| ✅ | `1. D 【详解】` | 题号、答案、标签是三个内容单元 |
| ✅ | `, 则` | 逗号与后续句子分开 |
| ❌ | `y=-11.7+1370.7` | 同一数学式内部，紧排 |
| ❌ | `所以y与x负相关` | 变量与正文紧排，是公式排版惯例 |

### C-04 为什么下标用 `_` 而不是 Unicode 下标字符

两个理由，第二个是决定性的：

1. **Unicode 下标字符极难输入**：`ᵤ`（U+1D64）没有键盘输入方式，只能复制粘贴，
   22 条里必然出现有人用 `ᵤ`、有人用 `u`、有人干脆省掉的混乱。
2. **大写下标字母在 Unicode 里根本不存在**。本题的补集符号下标是全集 `U`（大写），
   **没有任何 Unicode 字符能表示它**。硬求"逼真"只会逼出各人不同的变体，
   而**"统一"比"逼真"更重要** —— 真值标准一旦漂移就无法再作为基准。

`_` 是唯一能在全部 22 条上**统一表达**的方式，且是通行的纯文本约定。

> **关于它会不会影响实验**：六档协议处理的是**空白、大小写、全半角、标点、繁简**，
> **不涉及 `_`**。所以这个选择只会影响 CER 的**绝对水平**（对所有模型一致），
> **不影响协议敏感性**这一被测量。故可放心采用。

新增约定请追加到本表，并注明日期与理由。

## 五之二、数学类样本的特别提示

数学卷是 OCR 的**重灾区**，且错误有**强规律性**——认出一类，整页通杀：

| 类型 | 典型错认 | 说明 |
|---|---|---|
| 上标丢失 | `x²+3x` → `x+3x` | 上标常被整段吃掉，**全文逐处检查** |
| 运算符号当字母 | `∪` → `U`、`∩` → `n` | |
| 字母当运算符号 | `x` → `×` | 与上一条**方向相反**，都要查 |
| 花括号当圆括号 | `{ }` → `( )` | 集合与区间含义完全不同，**必须分开** |
| 补集符号被拆碎 | `C_U A` → `G4` | 下标 + 主字符被整体认错 |
| 根号 | `√` 常丢或变成 `v` | |
| 分号与逗号 | `,` `;` 在中英文里宽度不同 | 见纪律 3 |

**做法**：不要逐字扫，**按类型逐类查**——先通读一遍找上标，再找运算符号，再看括号种类。
比"从头到尾逐字看"快得多，也不容易漏。

## 六、已知易错清单（来自实跑对比）

| 易错 | 说明 |
|---|---|
| 千 / 干 | `千人茶会` 曾被认成 `干人茶会`，**同一张图里错了两处** |
| 个 / 人 | `10个月前` 曾被认成 `10人月前` |
| 聞 / 間 | 繁体 `新聞` 曾被认成 `新間` |
| `//` → `I/` | URL 里的双斜杠曾被认成字母 `I` 加斜杠 |
| 竖线 `\|` → `」` / `「` | 分隔竖线曾被认成弯引号 |
| 图标 `≡` → `三` | 图标被当成汉字写进真值 |
| 冒号宽度 | 全角 `：` 曾被认成半角 `:` |
| 误增字符 | `韩帅南` 曾被认成 `韩制师南` |

**用法**：改完一条后，拿这张表扫一眼——**不是让你硬找错，而是提醒这几类容易被忽略**。
